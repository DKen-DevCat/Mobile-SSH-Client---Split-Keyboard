# セキュアターミナルアプリ 要件・設計書

Oct 30, 2026 · @dken（2026-10-30 の指示で上書き更新し、同じ日に最低 OS を 17 に見直した。変えた点は「この版で決めたこと」）

## 概要

iPhone と iPad 向けに、SSH 先のシェルを操作するネイティブのターミナルアプリ「Mobile-SSH-Client---Split-Keyboard」を作る。処理は接続先の PC が担うので、アプリはフロントエンドに徹し、通信の速さと操作感を最優先にする。**横持ちだけ**で使い、左右に分けた自前のキーボードでシェルを挟む。設定は Ghostty のように **config ファイル 1 枚**で管理する。使うのは自分 1 人なので、配布は lfm3-vl-server の iPhone アプリと同じ**無料の署名と Mac からの自動の入れ直し**で行う。拡張として、Haiku を指揮役にしたエージェントハーネスも作る。

- **背景**：Termius の不満。色味が弱い、ターミナルと別に入力欄（Ask AI）がある、キーボードの開閉が面倒、横持ちで打ちにくい。
- **主な用途**：自分の Mac に SSH し、シェルや Claude Code を操作する。
- **対象端末**：iPhone 13 mini を基準に設計し、iOS / iPadOS 17 以降の iPhone（XS・XR・SE 第 2 世代以降）と iPad（第 6 世代以降）をすべて横持ちでサポートする。画面の大きさごとに作り分けず、1 つのレイアウト算出で iPhone SE から iPad Pro 13 インチまで扱う。

## 設計原則と性能目標

アプリの仕事は「打った瞬間に送り、届いた瞬間に描く」こと。サポートする最も遅い端末（iPad 第 6 世代、A10 チップ）でも、次の目標を満たす。エージェントの応答速度は対象外で、拡張のハーネスで扱う。

- **端末ごとに作り分けない**：画面サイズと入力手段からレイアウトを算出する 1 つの仕組みで、iPhone も iPad も同じ品質にする。
- **メインスレッドを空ける**：受信データの解釈は別スレッド、描画は Metal で行う。大量の出力が流れていても、タッチやキー入力が遅れない。
- **計測で守る**：目標値を計測ポイント（signpost）と自動テストで毎ビルド確認する。

| 指標 | 目標 | 測り方 |
| --- | --- | --- |
| キー入力→送信 | 16ms 以内（1 フレーム） | 指を離してから送信までの区間（signpost `keyToSend`） |
| 受信→画面反映 | 次のフレーム（60Hz 端末で 16ms、120Hz 端末で 8ms） | 受信からフレーム表示まで（`frame`） |
| スクロール | 画面のリフレッシュレートを維持（60 / 120fps） | 1 万行のスクロールバックでフレーム落ちなし |
| 大量出力 | 入力が止まらない。描画は間引いて最新を表示 | 10MB の出力中にキー入力が通る |
| 起動→入力可能 | 1 秒以内（ネットワーク往復を除く） | コールド起動から |
| 復帰→再接続 | 1 秒以内（ネットワーク往復を除く） | バックグラウンドからの復帰（`reconnect`） |
| 待機中 | 画面に変化がなければ描画しない | 消費電力 |

## 全体アーキテクチャ

アプリは 7 つの部品でできており、入力は左側を下って接続先へ、接続先の出力は右側を上って画面へ戻る。設定ファイルはすべての部品に値を配る。

```
            [設定ファイル config（1 枚）] ── 読み直し ──▶ すべての部品
                                                    
 [分割キーボード / ハードウェアキーボード / タッチ]       [Metal 描画（グリフアトラス）]
                 │                                            ▲
                 ▼                                            │ 画面の写し（1 フレーム 1 回）
          [入力ルータ] ◀── マウス報告・代替画面・括弧付きペースト ── [エミュレータ（SwiftTerm、別スレッド）]
                 │                                            ▲
                 ▼                                            │
          [SSH（swift-nio-ssh ＋ Network.framework）] ──────────┘
                 │  TCP（keepalive）
                 ▼
          [接続先の PC：tmux]
```

キー入力とタッチは入力ルータでバイト列になり、SSH で接続先へ送られる。接続先の出力はエミュレータが専用のキューで解釈し、Metal が次のフレームで描く。エミュレータは「マウス報告の有無・代替画面かどうか・括弧付きペースト」を入力ルータへ伝え、同じジェスチャやキーの送り先と形を切り替えさせる。

## 画面構成

横持ちだけ。レイアウトは画面サイズと入力手段から算出する。iPhone 13 mini では、左 198pt・右 228pt のキーボードで中央 282pt のシェルを挟む。キーボードの枠は分割もフリックも同じにし（フリックは枠いっぱいに並べる）、切り替えてもシェルの桁数が変わらないようにする。シェルは画面の上端から下端までを使い、状態とタブの「上の 2 行」がその上に重なる（下のバーは無い。シェルの表示範囲は縮めない）。

### レイアウトの決め方

寸法は端末ごとの固定値で持たない。「画面サイズ・セーフエリア・ハードウェアキーボードの有無・キーボードの種類」から毎回算出する（`LayoutEngine`）。回転・窓の大きさの変化のたびに算出し直し、桁数と行数が変われば接続先へ知らせる（SSH の window-change）。

1. **キー 1 つの大きさ（u）** = 画面の短辺 × 0.064 を切り捨てた整数を 24〜36pt に収める（13 mini で 24pt、iPad で 36pt）。文字キー（1u）は u×u の正方形。config の `keyboard-pitch` があればその値を u にする（20〜80pt。意味は「キー 1 つの大きさ」）。
2. **キーボードの幅** = 左は 8.25u、右は 9.5u（Magic Keyboard の JIS 本体の 14.5u を二つに分けた幅。13 mini で 198pt と 228pt）。内側の端は実物どおり段ごとにずれ、外側の端（左の面は左端、右の面は右端）はそろう。
3. **キーボードの高さ** = 5.6u（F キーの段が 0.6u、ほかの 5 段が各 1u。13 mini で 134.4pt）。左右で同じ高さ。分割もフリックも同じ枠で、下寄せ（下のセーフエリアの上まで）。フリックの面は、この枠いっぱいに 5 段を等分して並べる。上の 2 行には重ならない: 5.6u が「画面の下端 − 上端 − 上の 2 行の高さ 52pt」を超えるなら、u をその高さに収まるまで縮める（切り捨て）。1 段の高さの目安（`rowHeight`）は u。
4. **シェル** = 左右のキーボードの間から、隙間 8pt ずつを引いた幅。高さは画面の上端（上のセーフエリアの下）から下端（下のセーフエリアの上）まで。かな漢字変換を使うキーボードのときだけ、下端に候補バー 34pt を置き、シェルはその上まで。

面の単位（8.25・9.5・5.6）は `KeyboardLayouts` の 1 か所で持ち、`LayoutEngine` と面の並びが同じ値を使う（テストで面と一致することを確かめる）。
5. **上の 2 行** = セーフエリアの左右いっぱい、上端から。1 行目（状態）は高さ 20pt、そのすぐ下の 2 行目（タブ）は 32pt。シェルの上に前面で重ねる。
6. **シェルの角**：左下に 📎、右下にキーボード選択のボタン。どちらも 36pt の丸で、シェルの端から 6pt 空ける（候補バーがあればその上）。キーボード選択は分割のときだけ。📎 は、画面のキーボードを出している間（分割）は隠す（キーボードの左下の 📎 のキーから同じメニューを出す）。ハードウェアキーボード・狭い窓では残る。
7. **狭い窓**：シェルが 200pt を割るなら u を縮める（u = 切り捨て((内側の幅 − 200 − 16) ÷ 17.75)。17.75 は 8.25 + 9.5）。18pt を割るほど狭ければ（低くても同じ）、画面のキーボードを隠してシェルだけにし、知らせる。
8. **ハードウェアキーボード**：つながっていれば画面のキーボードを出さず、シェルを全面に広げる（config の `soft-keyboard-with-hardware` で出し続けることもできる）。狭い窓も同じく、シェルは左右いっぱい・上端から下端まで。どちらも上の 2 行と 📎 はあり、キーボード選択は出さない。

| --- | --- | --- | --- | --- | --- |
| iPhone SE（第 3 世代） | 667×375 | 24 | 198 / 228 | 225×375 | 45×37 |
| iPhone 13 mini（基準） | 812×375 | 24 | 198 / 228 | 282×354 | 57×34 |

| iPhone 16 Pro Max | 956×440 | 28 | 231 / 266 | 319×419 | 64×40 |

キーボードの高さは 5.6u（13 mini で 134.4pt、iPad で 201.6pt）。シェルの高さは上端から下端まで（上の 2 行に隠れる分も含む）。桁は 13 mini の旧い値（シェル 344pt で 70 桁）に比例させた目安（シェルの幅 × 70 ÷ 344 の切り捨て）、行は既定のフォント（SF Mono、`font-size = 10` の 85%）で文字セルを物理ピクセルの整数に丸めた目安。上の 2 行（52pt）が、シェルの上の約 5 行に重なる。かな入力のときは候補バーの分だけ行が 3 行ほど減る。

- **上の 2 行**：シェルの上に前面で重なる。背景は透明で、ボタンの上だけがタッチを受け、空いた所はシェルに通す。
  - **1 行目（状態）**：左に時計、右から 電池（％）・通信・⚠・表示倍率（85% / 100%。タップで段を巡る）。⚠ は config に読めない行があるときだけ出し、タップで行番号を見せる。Face ID の iPhone の横持ちでは iOS が状態バーを出さないので、その代わりに時計・通信・電池を出す。iPad など iOS が状態バーを出しているときは隠す（二重に出さない）。
  - **2 行目（タブと＋）**：左端から接続タブ、最後のタブの右隣に＋。はみ出したら左右にスライドする（選んだとき・足したときは、今のタブと＋が見える所までスライド）。タブと＋は不透明。
- **シェルの角**：左下に 📎（メディアを送る。画面のキーボードを出している間は隠し、キーボードの 📎 のキーから同じメニューを出す）、右下にキーボード選択（今のキーボードの短い名前を出す丸いボタン。タップで 5 つから選ぶメニュー。分割のときだけ）。
- **タブ**：左上から並ぶ。タップで切り替え。切れたタブをもう一度タップすると繋ぎ直す。長押しで「閉じる」。
- **＋**：タップで新しいタブ。接続先は、今のタブと同じ host、無ければ `auto-connect` の host、無ければ最初の host（どれも無ければ「設定を編集」）。長押しでメニュー：config の `host` の一覧（選ぶとその接続先の新しいタブ）、公開鍵をコピー、設定を編集、設定を読み直す、このタブのホスト鍵を忘れる。
- **システムのジェスチャ**：キーボードが画面の下端と左右の端に触れるので、端からのジェスチャを後回しにし（1 回目のスワイプはアプリが受ける）、ホームインジケータを隠す。

## 設定ファイル

Ghostty と同じく、**config ファイル 1 枚**ですべてを決める。設定画面は作らない。

### 書き方

- 1 行に `key = value`。`#` で始まる行と空行は読み飛ばす。値の前後の空白は除き、空白を残したいときは `"..."` で囲む。
- 値を空にする（`key =`）と既定値に戻る。
- `palette`（番号ごとに上書き）と `host`（書いた順に足す）は何度でも書ける。
- 読めない行は飛ばし、ほかの行は使う。読めなかった行は上の 1 行目の ⚠ と、編集画面の下に行番号付きで出す。1 行の誤りで全体を捨てない。
- 秘密は書かない。鍵は Secure Enclave、ホスト鍵はキーチェーン、パスワードは毎回聞いて保存しない。

## 入力設計

入力はすべて「入力ルータ」に集め、バイト列に変えて接続先へ送る。画面の 2 種類のキーボードと、iPad のハードウェアキーボードを同じルータにつなぐ。キーの変換（xterm 互換）は `KeyEncoder` にまとめ、テストで固定する。

### 改行と送信

- **送信**：⏎（return / 送信）は CR（\r）を送る。変換中の⏎は確定だけで、接続先には何も送らない。
- **改行**：既定（`newline = auto`）は「接続先が括弧付きペーストを有効にしていれば、改行 1 文字を貼り付けとして送る。無効なら ESC+CR を送る」。`esc-cr`・`ctrl-j` を config で選べる。zsh、bash、Claude Code、vim、tmux の中で実機検証してから確定する。

判断基準は 3 つ。①改行のつもりで押してもコマンドが実行されないか（安全性）、②主要なアプリで改行として効くか、③他の操作と取り違えられないか。

| 方式 | 送るもの | ①安全性 | ②効く場所 | ③取り違え |
| --- | --- | --- | --- | --- |
| Ctrl+J | LF（1 バイト） | 低い。bash・zsh では実行と同じ扱い | Claude Code など一部のアプリ | 起きない |
| ESC+CR | ESC と CR（2 バイト） | 高い。zsh は改行を挿入する | zsh、Claude Code（Option+Enter と同じ信号） | ESC 単体と読まれる余地がある（vim など） |
| 括弧付きペースト | 改行 1 文字を貼り付けの印で挟んで送る | 高い。貼り付けた改行は実行されない | 括弧付きペーストを有効にしたアプリ（zsh、新しい bash、Claude Code など） | 起きない。有効かどうかはエミュレータが接続先の要求から把握できる |

### キーボードの種類（🌐 で切り替える）

| 種類（`keyboard`） | 面 | 入力 |
| --- | --- | --- |
| 分割キーボード（ローマ字）`romaji` | JIS の分割 | 英字をローマ字としてかなにし、かな漢字変換する |
| 分割キーボード（英語）`english` | JIS の分割 | そのまま送る |
| 日本語フリック分割 `kana` | かなのフリック | かな漢字変換する |
| 英語フリック分割（ローマ字）`flick-romaji` | 英字のフリック | 英字をローマ字としてかなにし、かな漢字変換する |
| 英語フリック分割（英語）`flick-english` | 英字のフリック | そのまま送る |

- **🌐**：タップで前のキーボードへ戻る。長押し（0.45 秒、ほかのキーに使っていなければ）で、iOS の吹き出し（ポップオーバー。iPhone でも吹き出しのまま）から 5 つを選ぶ。シェルの右下のキーボード選択のボタンからも同じ 5 つから選べる。押しながら矢印などを押すと fn の層。右の面には 🌐 が 2 つあり（内側の `globe-inner` と外側の `globe`）、どちらも同じ働き。長押しは、キーの ID ではなく fn の修飾キー（`.modifier(.fn)`）で見分ける。
- フリックの面では、ABC で英語フリック（英語）へ、あいう で日本語フリックへ切り替える（iOS と同じ）。

### JIS の分割

利用者の Magic Keyboard（JIS）の写真（2026-10-31）から、日本語（かな）の刻印を外した配列。

- **実物の比率**：左右・全段で共通の単位 u を使い、文字キー（1u）は u×u の正方形。F キーの段の高さは 0.6u（ほかの段は 1u。面の高さは 5.6u）。各段の幅は Magic Keyboard の JIS（本体 14.5u）に合わせ、内側の端は実物どおり段ごとにずれる（そろえない）。外側の端はそろえる（左の面は左端、右の面は右端。`KeyboardFace` の向き `leading` / `trailing` と、面の幅を表す `gridUnits` で、短い段を外側へ寄せる）。キーの無い隙間に触れたら、いちばん近いキー。

| 面 | 段（外側から。数字は u。書いていないキーは 1） |
| --- | --- |
| 左（左端をそろえる。幅 8.25） | esc 1.5・F1〜F6 ／ 1〜6 ／ tab 1.5・Q W E R T・Y ／ control 1.75・A S D F G・H ／ shift 2.25・Z X C V B・N ／ caps 1・option 1・command 1.25・空白兼ポインタ 4・📎 1 |
| 右（右端をそろえる。幅 9.5） | F6〜F12・🔒 1 ／ 6 7 8 9 0 - ^ ¥・delete 1.5 ／ Y U I O P @ [・return（上）1 ／ H J K L ; : ]・return（下）0.75 ／ N M , . / _・shift 1.25 ／ 🌐 1・空白兼ポインタ 3.25・command 1.25・🌐 1・◀・▲▼（上下に分ける）・▶ |

- **最上段（低い段）**：左は esc と F1〜F6、右は F6〜F12 と 🔒（アプリをすぐロック）。F キーは Mac の刷り込みの絵で描き、接続先には F1〜F12 を送る。段が低いので、高さが 20pt 未満のときは番号を省いて絵だけ描く（13 mini は 14.4pt）。esc などの文字も、段の高さに合わせて大きさを決める。
- **数字の段**：1〜0、−、^、¥、⌫。shift の記号は JIS（2 は "、6 は &、7 は '、− は =、^ は ~、¥ は |。0 は shift で何も変わらない）。¥ のキーは端末で使う \ を打つ（option で ¥）。
- **文字の段**：tab・Q〜P・@（`）・[（{）、control・A〜L・;（+）・:（*）・]（}）、shift・Z〜M・,（<）・.（>）・/（?）・_・shift。return は逆 L 字で 2 段にまたがる（下の「return」）。control は A の左（JIS の Mac と同じ）。
- **最下段**：左は caps lock（ランプ付き）・option・command・**空白兼ポインタ**・**📎**、右は **🌐**・**空白兼ポインタ**・command・🌐・◀・▲▼（上下に分ける）・▶。赤い丸のキーは無く、左右の空白キーがポインタを兼ねる（「ポインタ」）。赤い丸があった場所は、左の面が 📎（離したら、シェルの左下の 📎 と同じメニュー〔写真・動画を選ぶ／撮る／録音する／ファイル、送っている間は「送るのをやめる」〕を、そのキーを指す吹き出しで出す）、右の面が 🌐（今の 🌐 と同じ働き）。
- **左右で重ねる列**：6・Y・H・N（と F6）は左右の両方に置く。同じキーが、左の面の内側（右寄り）と右の面の内側（左寄り）に出る（右の面の左端は、左の面の 5u の位置。どちらの手でも打てる）。
- **F と J**：突起の印。押すと少し強く振動し、赤く光る。
- **return**：CR を送る。shift＋return は改行（`newline`）。実物の逆 L 字で、枠を 2 つ（上 1u の `send` と下 0.75u の `send-lower`。どちらも送信）に分け、つながって見えるように 1 つの形で描く（押した色も両方に出る）。
- **command**：接続先には届かない。アプリの操作に使う（⌘C コピー、⌘V ペースト、⌘−／⌘＝ 表示倍率、⌘T 同じ接続先の新しいタブ、⌘W タブを閉じる、⌘1〜⌘8 その番号のタブ、⌘9 最後のタブ）。
- **caps lock**：押すたびに入・切。英字だけ大文字になる（Mac と同じく、shift と重ねても大文字のまま）。
- **option**：`option-as-meta` なら meta（ESC 前置）。キーに刷ってある option の文字（¥）が先に効く。

### ローマ字入力

`romaji` と `flick-romaji` では、英字をローマ字としてかなにし（`RomajiConverter`）、かな漢字変換の読みに足す。Mac の日本語入力と同じ規則で、`nn`・`n'` で「ん」（その場で「ん」になるので、こんにちは は n を 3 回）、n の後に子音で「ん」、同じ子音の重ねで「っ」、`x`・`l` で小さい文字、`,` `.` `-` `[` `]` `/` は「、」「。」「ー」「「」「」」「・」。

- **読みはその場に出す**：変換中の読み（かなと、まだかなにならない英字）は、シェルのカーソルの位置に、端末と同じ字体と大きさで下線付きに重ねる（iOS の変換中の文字と同じ。背景は端末の背景色、下線はアクセント色）。キーを押した瞬間に同期で更新し、候補の変換は待たない。右端からはみ出すなら左へずらして収める。カーソルを隠す画面（Claude Code など）でも、端末の持つカーソルの位置に出す。スクロールバックを見ている間は重ねない。確定・取り消しで消える。重ねるのは 1 枚のラベル（UILabel）で、文字か位置が変わったときだけ更新する（描画の負荷を増やさない）。
- まだかなにならない英字は、候補バーの先頭にも薄く出す。⌫ はそこから消す。
- **空白で変換**：いちばん上の候補で確定する（候補をタップすれば、その候補で確定）。**⏎ は読みのまま確定**（接続先には何も送らない）。ほかのキーは確定してから送る。

### ポインタ（空白キーと兼用）

ノートパソコンのトラックパッドのように、ポインタ（矢印）を動かす。専用のキーは置かず、左右の空白キー（分割の `space-l`・`space-r`、フリックの最下段 `space-b`）が空白とポインタを兼ねる（`KeyAction.spacePointer`）。見た目は空白キーの中央に小さな赤い丸。フリックの 2 段目の「空白」キーは普通の空白で、長押しの動きも今までどおり（「同時入力」）。

判定は TermCore の純粋な状態機械 `SpacePointerGesture` にまとめる（画面にも時計にも頼らない。入力は触れた・動いた・離れた〔指 ID・左右・位置・時刻〕とほかのキーを打ったこと、出力は空白・左クリック・右クリック・ポインタを動かす）。テストで固定する。

| 操作 | 起きること |
| --- | --- |
| 動かさずに離す | 空白。修飾キー・ローマ字の変換・先行表示は、今の空白キーと同じ道（`KeyboardModel.commit` に `.character(" ", …)` として渡す） |
| 触れた点から 6pt（`SpacePointerGesture.slop`。`PointerStick.tapSlop` と同じ）より動かす | その指がポインタを動かす。その指では空白を打たない。指は枠の外まで滑らせてよい |
| ポインタを動かした指を離してから 1.0 秒（`SpacePointerGesture.graceTime`）以内に、動かさずに離す | 空白ではなく左クリック（振動つき）。クリックしたら 1.0 秒を数え直す（続けて叩けばダブルクリック） |
| 間にほかのキーを打つ（文字・矢印・修飾キーなど） | 1.0 秒の猶予が終わる。その後のタップは空白 |
| 左右の空白兼ポインタを同時に押す（2 本目が触れた時、1 本目がまだ触れている） | 右クリック（振動つき）。その 2 本の指はどちらも空白を打たない |

- **猶予の測り方**：ポインタを動かした指を離した時刻（クリックしたら、そのクリックの指を離した時刻）から、動かさずに離した時刻までが 1.0 秒以内か。右クリックは猶予に関わらない。
- **動かし方**：トラックパッド式。指の動いた分だけポインタが動き、速く動かすほど遠くへ届く。止めれば止まる。指の速さ（pt/秒）に応じた倍率を掛ける（60pt/秒以下で 0.9 倍、900pt/秒以上で 3.2 倍、その間は滑らかに増える。`PointerCurve`）。ポインタを動かす指は同時に 1 本だけで、6pt を超える動きは触れた点からまとめて動かす。
- **動ける範囲**：シェルと、上の 2 行（左右いっぱい）。外へ出る動きは、範囲の中でいちばん近い点に寄る。初めはシェルの中央から。
- **クリックの行き先**：ポインタの下にあるもの。
  - シェル：タップと同じ（マウス報告・入力行のカーソル移動）。右クリックは 2 本指のタップと同じ（マウス報告・編集メニュー）。
  - 上の 2 行：その下のタブ・＋・倍率・⚠ を押す（＋は新しいタブ。メニューは長押しなので出ない）。右クリックは何もしない。
  - キーボード選択のボタン：キーボードを選ぶ吹き出しを出す。📎 の上は何もしない（📎 が隠れている間は、そこにあるものとして扱わない）。
- **手応え**：触れた瞬間の軽い振動はほかのキーと同じ。クリックには押し込んだ手応えの振動を返す（3D Touch のような感触。右クリックは強く 2 回）。`haptics` で切れる。
- **矢印**：Mac の矢印の約 0.75 倍（小さめ）。文字を打つと隠れる（Mac と同じ）。ロック中は動かさず、押せない。
- **長押しでトラックパッドにはしない**：空白兼ポインタを長押ししても、キーボードはトラックパッドにならない（フリックの 2 段目の「空白」だけ。「同時入力」）。

### フリックの分割（日本語・英字）

- iOS の 12 キーをそのまま、左右に 1 面ずつ置く。どちらの面からも同じシェルに入力する。上の段（esc〜alt・⌨・矢印）は置かない。
- 最下段の両端を改行（↩︎）と送信（send）に置き換える。外側が改行、内側（中央寄り）が送信で、中央に送信が 2 つ並ぶ。

|  | 左下 | 右下 |
| --- | --- | --- |
| 左キーボード | 改行 ↩︎（☺ の位置） | send（⏎ の位置、縦 2 マス） |
| 右キーボード | send（☺ の位置） | 改行 ↩︎（⏎ の位置、縦 2 マス） |

- その下にもう 1 段を置く。左は「🌐・空白兼ポインタ（幅 3）・📎」、右は「🌐（`globe-inner`）・空白兼ポインタ（幅 3）・🌐」。2 段目の「空白」キーは普通の空白。
- フリックの面は、分割と同じ枠（左 8.25u・右 9.5u、高さ 5.6u）の画面の下に寄せて置き、枠いっぱいに 5 段を等分して並べる（配置は `LayoutEngine`）。13 mini では 1 段が約 27pt と低いので、実機で打ちやすさを確かめる（「未決事項」）。
- **ガイド**：フリックのキーを押した瞬間に、そのキーの上（中央）と上下左右（その方向に文字があるものだけ）へ、キーと同じ大きさの四角を十字に出して文字を描く（iOS のフリックと同じ）。指の向きの四角をアクセント色、ほかを押した色にし、指を動かすたびに更新する。離す・取り消しで消える。ウィンドウの外にはみ出す四角は内側へずらす。キーボードの外（シェルや上のバーの前面）まで出るので、ウィンドウの全面を覆う、タッチを受けない層に 1 度だけ足して使い回す（画面のビューに四角を足し引きすると、画面全体の配置をやり直させる）。
- **方向のしきい値**：押したキーの大きさで決める（`FlickDirection.threshold(keySize:)` = 短い辺 × 0.3 を 8〜16pt に。13 mini のフリックのキー（幅 36pt）で約 11pt）。端末ごとの値は持たない。
- **日本語**：フリック（離した位置で方向を決める）と、同じキーの連打（トグル入力。1 秒以内）の両方で入力できる。「→」で連打を区切り、「゛゜小」で直前の文字を濁点・半濁点・小さい文字に順に変える。ABC で英字のフリックへ。
- **英字**：iOS の ABC と同じ並び（@#/&_・abc・def・ghi・jkl・mno・pqrs・tuv・wxyz・'"()・.,?!、左上に -+=*%）。小文字で、a/A を押すと大文字（入・切）。連打のトグルは使わず、フリックで選ぶ。あいう で日本語のフリックへ。
- 変換中の読みはシェルのカーソルの位置に下線付きで出し（「ローマ字入力」）、候補は中央の候補バーに出す。候補をタップで確定。⏎ は確定だけ、⌫ は読みを 1 文字消す、ほかのキーは確定してから送る。
- **かな漢字変換**：AzooKeyKanaKanjiConverter（同梱の辞書）で変換する。変換は裏のキューで行い、打つたびの古い頼みの結果は捨てる（キー入力を待たせない）。辞書を開くまでと、辞書に無い語のために、読みそのままとカタカナを最後に並べる。文節の候補を選ぶと、その分だけ確定して残りは変換中のまま。候補バーのボタンは使い回す（打つたびに作り直さない）。
- **学習しない**：打った語を変換器の学習データとしてディスクに残さない（「セキュリティ要件」）。絵文字と特殊な候補（日時・計算など）も出さない。

### 先行表示（直接送る文字を、返事を待たずに出す）

mosh の考え方。直接送る文字（英語の分割・英語フリック・ローマ字でかなにならない文字）を、接続先が返す前に、カーソルの位置へ薄く出す（通信の往復の分だけ遅れて見える、を消す）。判断は純粋な `EchoPredictor`（TermCore、テスト付き）が行い、重ねる描画は「ローマ字入力」の読みと同じ層を使う（読みがあるときは読みが優先）。

- **確かめられたときだけ出す**：打った文字が、打った時のカーソルの位置に実際に返ってきた（画面のその位置の文字が同じになり、カーソルが進んだ）のを 1 度見てから。最初の 1 文字は出さない。パスワードの入力では文字が返らないので、決して出ない。空白は返ってきても画面のセルが空のままなので、カーソルが同じ行でその桁より先へ進んだことで返ってきたとみなす（空白を挟んで打っても、確かめた状態が続く）。
- **外れたら消して、確かめ直す**：その位置の文字が違う、カーソルが手前や別の行へ動いた、1 秒たっても返らない（`EchoPredictor.timeout`）。返ってきた文字は、本物（Metal の描画）に置き換わる。
- **Enter・Esc・Tab・control／option との組み合わせ・貼り付け**：予測を消して、確かめ直す。**⌫・矢印**：予測を消すだけ。
- **出さない場面**：カーソルが隠れている、スクロールバックを見ている、選択中、変換中。代替画面・マウス報告では止めない（tmux は外側の端末を代替画面にし、`mouse on` ならマウス報告も使うので、止めると既定の tmux でほぼ働かない）。tmux・vim・less の中でも、上の「確かめられたときだけ出す」「外れたら消して、確かめ直す」の規則で守る（vim の通常モードなどは、返る文字が予測と合わないので確かめが通らず出ない）。対象は ASCII の印字できる 1 文字（0x20〜0x7E）だけで、かなや記号の変換結果は予測しない。
- **見た目**：前景色を薄く（不透明度 0.55）、点線の下線。背景は端末の背景色。右端を越える分は出さない。
- **突き合わせ**：画面を描くたびに（`terminalViewFrame` で得た画面と）。描画が止まっていても 1 秒後に突き合わせて消す。予測はメモリだけに置き（ディスクに書かない）、タブを替えたら捨てる。

### 同時入力（両方のキーボードで共通）

- 左右のタッチを指ごとに独立して追跡し、両手で同時に押しても取りこぼさない。
- 文字は指を離した時点で確定し、出力順はその確定順とする（同時に離れた指は時刻順）。フリック方向も離した位置で決まる。
- 修飾キーは、Mac のキーボードと同じく押している間だけ効く（離すと外れる。長押ししてもリピートせず 1 回）。左右の面で状態を共有するので、左の shift と右の文字のように両手で押す。caps lock だけは押すたびに入・切。
- ⌫ と矢印キーは長押しでリピートする（`key-repeat-delay`・`key-repeat-interval`）。
- 触れた瞬間に軽い振動を返す（`haptics`）。F と J は少し強い。振動とハイライトは、タッチの最初に（ほかの処理より先に）返す。
- **画面の端のタッチの遅れを取る**：画面の端は、iOS のシステムのジェスチャ（ホームバーの上スワイプなど）の判定が終わるまでタッチが届かず、端のキーが遅れる。`preferredScreenEdgesDeferringSystemGestures = .all` は残したまま、ウィンドウのジェスチャの `delaysTouchesBegan` を false にして（公開の API。画面に載ったとき・配置のたびにかけ直す）、遅れを取る。
- **空白の長押しでトラックパッド**：フリックの 2 段目の「空白」キーだけ（分割の空白キーと、フリックの最下段は空白兼ポインタなので起こさない）。0.5 秒、6pt 以上動かさずに押し続けると、キーボード全体がトラックパッドになる（iOS 標準のキーボードと同じ。文字と絵が薄くなり、キーの面だけに見える。振動 medium）。その指の動きはポインタ（「ポインタ」）を動かし、離すと元に戻る（空白は打たない。動かさずに離してもクリックにしない）。トラックパッドの間にほかの指で軽く叩くと、左クリック（`PointerStick.click(right:)`。触れていた時間が `PointerStick.tapTime` 以内、動きが `PointerStick.tapSlop` 以内。キーは打たない。叩かずに長く触れていたり動かしたりしても何も起きず、取り消しも何もしない）。0.5 秒より前に離せば、今までどおり空白を打つ。待つ間に 6pt 以上動いたら、トラックパッドには入らない（離したら空白）。空白兼ポインタに触れている間は入らない。

### iPad：ハードウェアキーボード

- 物理キーの押下を同じ入力ルータに流す。ctrl、option、esc、矢印、F キー、home / end / page をそのまま送る。押し続けるとリピートする。
- つながったのを検知したら画面のキーボードを隠し、シェルを広げる。外れたら戻す。
- command の組み合わせはアプリ内操作（コピー・ペースト・倍率）。
- ハードウェアキーボードでの日本語入力（iPadOS の変換）は後続タスク（UITextInput が要る）。

### 入力行のネイティブ編集（後続タスク）

入力行では、iOS のテキストボックスと同じく、タップでカーソル移動、長押しで虫眼鏡、ドラッグで範囲選択ができ、編集メニューが出るようにする。

- **今できること**：入力行（カーソルのある行）をタップすると、その位置までカーソルを矢印キーで動かす（全角は 1 文字として数える）。
- **仕組み（後続）**：入力行の文字を写した「影のテキスト」を iOS の文字入力の仕組み（UITextInput）に渡し、iOS 標準のカーソル・選択・編集メニューをそのまま使う。影のテキストへの操作は、矢印キー・削除・文字の送信に翻訳して接続先へ送る。
- **入力行の範囲**：シェルが出す区切り情報（OSC 133）で特定する。区切り情報がないとき（Claude Code など）は、カーソルのある行を入力行とみなす簡易モードにする。

## メインシェルのタッチ操作

マウスの代わりに「タップ＝クリック」「縦ドラッグ＝スクロール」を基本操作とする。シェル上のアプリがマウス報告を求めているかどうかで送り先を切り替える。

### 3 つのモード

エミュレータが接続先の要求（マウス報告のオン・オフ、代替画面への切り替え）を入力ルータへ伝え、ルータがモードを決める（`GestureMode`）。

- **通常**：普通のシェル。ジェスチャはアプリ内で処理する。
- **マウス報告あり**：vim、tmux、htop などがマウスを要求しているとき。タップやスクロールをマウスイベント（SGR 形式）として送る。config の `mouse-reporting = false` で止められる。
- **代替画面・マウス報告なし**：less や man など。スクロールを ↑↓ キーとして送る。

| 操作 | 通常 | マウス報告あり | 代替画面・マウス報告なし |
| --- | --- | --- | --- |
| タップ（入力行） | その位置へカーソルを移動 | 左クリック | なし |
| タップ（それ以外） | 選択を外す | 左クリック | なし |
| 縦ドラッグ | スクロールバック（履歴）を遡る | ホイール | ↑↓ キー |
| 長押し→ドラッグ | 選択。指を離したら自動でコピー（メニューは出さない） | 同左（接続先へは送らない） | 同左 |
| ダブルタップ | つながった文字列を選び、選んだ瞬間に自動でコピー | 同左（ダブルクリックは送らない） | 同左 |
| 2 本指タップ | 編集メニュー（ペーストなど） | 右クリック | 編集メニュー |
| ピンチ | 表示倍率の変更 | 同左 | 同左 |

### 選択とコピー

選ぶと、確認の表示を出さずに自動でクリップボードへコピーする（当然の動きとして黙ってやる）。選んだ範囲の色は残り、タップ・キー入力で外れる。ダブルタップ・長押しの終わりで編集メニューを自動では出さない（2 本指タップのメニューは今までどおり）。⌘C と編集メニューの「コピー」も同じコピーの関数を使う。公開鍵のコピーは対象外（秘密ではない）。

- **ダブルタップで選ぶ「つながっている文字列」**：空白で区切られたひとかたまり（URL・パス・`a=b&c` など）。範囲と、コピーする文字を決める部分は、画面にも SwiftTerm にも頼らない純粋な関数（TermCore の `ConnectedText`。セルの文字・幅と折り返しの印は、呼び手が行ごとに渡す）にあり、テストで固定する。`TerminalEngine.connectedText` がロックの中で行を読んで渡す。
  - **区切り**：空白・タブ・空のセル、罫線とブロックの文字（U+2500〜U+259F。Claude Code の入力欄の枠を含めないため）。全角の続きのセル（幅 0）は前の文字の一部。区切りの上をタップしたら何も選ばない。
  - **行をまたぐ**：次の行へつなげるのは、その行の最後の桁まで続いていて、①次の行が折り返しの続き（`isWrapped`）、または②次の行の先頭の桁が区切りでないとき（tmux の中の折り返しはこちら）。前の行へも同じ考えでつなげる。つなげるのは、タップした行を含めて最大 50 行（`ConnectedText.maxLines`）。
  - **コピーする文字**：行をまたいでも改行を入れずにつなげた文字（全角の続きのセルは数えない）。
- **長押し→ドラッグ**：指を離したとき（`.ended`）にコピーする。
- **クリップボードの扱い**（`UIPasteboard.general`、`localOnly`。期限の規則は TermCore の `ClipboardLease`）：
  - アプリが前面にいる間は期限を付けない。
  - アプリを離れたら（`UIScene.didEnterBackgroundNotification`）、中身がまだアプリの載せたもの（`changeCount` が覚えた値と同じ）で、`clipboard-clear` が 0 より大きければ、同じ文字を期限（今 + `clipboard-clear`、既定 60 秒）付きで載せ直す。期限は OS が管理するので、アプリが止められても効く。新しい `changeCount` を覚える。
  - 前面に戻ったら（`UIScene.didActivateNotification`）、まだアプリの載せたもので、付けた期限がまだ来ていなければ、期限を外して載せ直す。期限を過ぎていたら何もせず、覚えていた文字を捨てる。
  - 中身は読まない（iOS の「ペーストの許可」が出るので、比べるのは `changeCount` だけ）。載せ直し用の文字はメモリにだけ持つ。`clipboard-clear = 0` は今までどおり消さない。
  - 構造的に残るリスクは「セキュリティ要件」と issue #4。

### 細かい挙動

- **スクロール量**：ドラッグ量を行の高さで割り、行単位にそろえる（端数は持ち越す）。どのモード（通常・マウス報告・↑↓キー）でも、指を離した時点で止まる（慣性は無い。離した後にスクロールを呼ぶ道が無い）。
- **最下部に戻る**：スクロールバック中にキーを押したら、最下部（入力位置）へ戻る。スクロールバック中は右端に細い印を出す。新しい出力が来ても、見ている行は動かさない。
- **ピンチ**：`zoom-steps` の段（既定 85% と 100%）で止まる。1 回のピンチで 1 段。上の 1 行目の倍率ボタン（段を巡る）と command＋−／＝ でも切り替える。
- **タップの位置**：タップした点を文字セルの行・列に変換して送る。範囲の外は端のセルに寄せる。
- **タップを待たせない**：ダブルタップを待ってからタップを処理することはしない（1 回目のタップはすぐ効く）。

## 描画と解像度

物理ピクセルと 1 対 1 になる解像度で Metal 描画し、文字をピクセル境界にそろえる。これで 85% 表示の 8.5pt でも文字が滲まない。色は config の `color-space`（既定は Display P3）で出し、PC の Ghostty と同じ色に見えるように「色」の 4 段で合わせる。描画の仕組みは、サポートする最も遅い端末（A10）でも画面のリフレッシュレートを保てるように作る。

### 解像度

- **物理ピクセルで描く**：描画レイヤの倍率を画面の実倍率（`nativeScale`）に合わせる。iPhone 13 mini は画面を 3 倍で描いてから縮小しているため、そのままだと細い文字がぼやける。実倍率（約 2.88 倍）で描けば縮小を経由しない。iPad は 2 倍。
- **85% 時の文字の大きさ**：8.5pt は iPhone 13 mini で約 24px、iPad で 17px。
- **セルの寸法**：文字セルの幅と高さをピクセルの整数値に丸める。端数があると桁ごとに文字間隔がばらつく。
- **フレームレート**：画面のリフレッシュレートに合わせる（ProMotion 端末は 120Hz。`CADisableMinimumFrameDurationOnPhone`）。変化がないフレームは描かず、描画ループ（CADisplayLink）も止める。
- **描画負荷**：画面全体を 2 回のインスタンス描画（塗りつぶしと文字）にまとめ、A10 でも 1 フレームに収める。同じ背景色が続くセルは 1 つの四角にまとめる。

### 文字の描画

- 文字は物理ピクセルの大きさで 1 度だけラスタライズしてテクスチャにため（グリフアトラス、2048px 四方）、倍率やフォントを変えたときだけ作り直す。アトラスは最近傍で読む。
- 罫線とブロック文字（─ │ ┌ ╭ █ ▀ ░ など）はフォントを使わず図形として描く。行の間に隙間ができず、Claude Code や tmux の UI の枠がきれいにつながる。丸い角（╭╮╯╰）と二重線は、角の四角い 1 本線で描く。
- フォントは等幅英字（既定は SF Mono）に日本語フォールバック（Hiragino Sans）を組み合わせる。全角文字は 2 セル幅で描き、セルより狭い字形は中央に置く。
- **文字の太さ**（`font-thicken`、既定 false）：macOS の Ghostty にある「文字を太く描く」仕組みが iOS には無いので、グリフアトラスに書くとき（`GlyphAtlas.rasterize`）、文字の輪郭を細い線（文字の大きさの 1/40、最小 0.5px）でなぞって太らせる（描き方を塗り＋線にする）。設定を変えたら、`FontSpec` が変わるのでアトラスを作り直す。

### 色

手本は Mac の Ghostty。PC で見る画面よりスマホのアプリの色が薄く見えたので、原因を 4 つに分け、4 段で直す。

| 段 | 原因 | 直し方 |
| --- | --- | --- |
| ① true color が tmux の中まで届かない | tmux が 256 色に丸めている | tmux の起動で `COLORTERM=truecolor` を渡し、tmux 3.2 以上なら `-T RGB` も付ける（「接続の安定性」） |
| ② アプリ独自の配色 | 既定の配色が Ghostty と違う | `splitterm theme import` で、Ghostty が使っている値を config に書く（「Get Started と MCP」） |
| ③ 読みやすさの補正 | `minimum-contrast = 4.5` が暗い色を白へ寄せる | 既定を 1（補正しない。Ghostty の既定と同じ）にする |
| ④ 描き方 | 色空間・太字・文字の太さが違う | `color-space`（取り込みで Ghostty の `window-colorspace` を写す）、`bold-is-bright`、`font-thicken` |

見比べは `scripts/colortest.sh`（16 色・256 色・true color・Claude Code の色に近い見本・太字と通常）を、Ghostty とアプリで同じように流す。

- 24bit カラー（true color）に対応する。256 色の 16〜255 は xterm の標準の表（6×6×6 の立方体と灰色 24 段）。0〜15 は config の `palette`。
- **色空間**（`color-space`）：`display-p3`（アプリの既定）はテーマの値を P3 の座標として描くので、sRGB より彩度の高い色が出る。`srgb` は Ghostty の `window-colorspace` の既定で、PC と同じ色になる。取り込む（②）と Ghostty の値が書かれるので、Ghostty が既定のままなら `srgb` になり、P3 より少し落ち着く。キーボードとバーも同じ色空間で塗る。
- **最小コントラスト補正**（`minimum-contrast`、既定 1）：1 は補正しない。1 より大きくすると、文字色と背景色のコントラスト比がその値（例 4.5）を下回るとき、文字色を白か黒の側へ必要なだけ寄せる。暗い色が白っぽくなって薄く見えるので、既定では切る。色の組ごとに結果を覚えておく。
- **太字を明るく**（`bold-is-bright`、既定 false）：true なら、太字の文字で、文字色がパレットの 0〜7 のものを 8〜15 の色にする（256 色の指定 `38;5;N` の N が 0〜7 のときも同じ。true color と既定の文字色は変えない）。
- **色を決める規則**は `TermCore` の純粋な関数（`CellColorRules.resolve`）にあり、エミュレータや画面に頼らない（テストで固定する）。順に、太字を明るく → 反転（文字色と背景色を入れ替える）→ 薄く（dim。背景へ 40% 寄せる）→ 隠す（invisible。文字色を背景色にする）、隠さないなら最小コントラスト補正。`Theme` は SwiftTerm のセルをこの関数の入力に直して呼ぶだけ。
- **文字の太さ**（`font-thicken`、既定 false）：「文字の描画」を参照。
- テーマは config で編集できる。既定は高彩度のダークテーマとし、横持ちの試作と同じ配色にする。選べる配色（テーマ）は内蔵しない。Ghostty の配色は、取り込んで config に書く。

## 接続の安定性（切断対策）

スマホの SSH は、アプリがバックグラウンドに回るたび、電波が切り替わるたびに切れる。まず「SSH＋tmux＋自動再接続」で作業を失わない状態を作り、それでも不満が残るときだけ mosh 系の方式を足す。

### 何が問題か

- iOS はバックグラウンドのアプリを短時間で止めるので、SSH の通信（TCP）は切れる。
- 5G と Wi-Fi の切り替えで IP アドレスが変わると、TCP の接続は続けられない。
- 切れると、接続先で動いていたシェルや Claude Code のセッションごと終わる。

### 選択肢と判断基準

判断基準は 5 つ。①切れても作業が残るか、②復帰の速さ、③遅い回線での打鍵の体感、④接続先に追加するもの、⑤実装コストとライセンス。配布は自分の端末だけなので、ライセンスは「アプリを公開しない限り GPL の義務は生じない」が、手元のコードの扱いやすさとして残す。

| 方式 | 仕組み | ①作業 | ②復帰 | ③体感 | ④接続先 | ⑤実装・ライセンス |
| --- | --- | --- | --- | --- | --- | --- |
| SSH＋tmux＋自動再接続 | 復帰時に繋ぎ直し、tmux のセッションに戻る | 残る | ネットワーク往復 1〜2 回分 | 普通 | tmux | 軽い |
| mosh | UDP で通信し、IP が変わっても同じセッションを続ける。打った文字を先に表示する予測表示がある | 残る（スクロールバックは tmux 頼み） | ほぼ即時 | 良い | mosh-server | 重い。GPLv3 |
| Eternal Terminal | TCP で、切れても自動で繋ぎ直す | 残る | 速い | 普通 | etserver | 中くらい。Apache 2.0 |

### 手順

1. **MVP（実装済み）**：config の `host` に tmux のセッション名を持たせ（既定 `main`）、接続時にそのセッションへ入る（無ければ作る）。SSH の exec はログインシェルを通らず、`.zshrc` などに書いた PATH が効かないので、tmux の場所は自分で探す。
   - **探す場所と順**：接続先の `/bin/sh` が（ログインシェルが fish・tcsh でも壊れないように）、`/opt/homebrew/bin/tmux`、`/usr/local/bin/tmux`、`/opt/local/bin/tmux`、`$HOME/.nix-profile/bin/tmux`、`/run/current-system/sw/bin/tmux`、`/usr/bin/tmux` を順に試し、最初に実行できたものを使う。どれにも無ければ、ログインシェルの `command -v tmux`。この一覧は `HostEntry.tmuxSearchPaths` の 1 か所だけにあり、`splitterm doctor` も同じ一覧で探して、見つけた場所を出す。
   - **起動**：tmux 自体はログインシェル（`$SHELL -lc`）経由で `exec env COLORTERM=truecolor tmux -u new-session -A -s <名前>` として起動し、tmux のサーバーにログインの環境（PATH）を持たせる。
   - **true color を tmux の中まで届ける**（「描画と解像度」の「色」①）：tmux のクライアントに `COLORTERM=truecolor` を渡す。tmux 3.2 以上のときだけ、さらに `-T RGB`（この端末は true color、と tmux に伝える）と、新しいセッションへの `-e COLORTERM=truecolor`（`new-session -A -e COLORTERM=truecolor -s <名前>`。中で動く Claude Code などに伝わる）を付ける。3.2 以上かどうかは実際に試して決める（`tmux -T RGB -V` が成功すれば対応。3.2 未満は `-T` を知らず失敗する）。通らなければ今までどおりの起動（256 色）。1 行・外側の単一引用符の中に単一引用符を入れない・`/bin/sh` に任せる・tmux の探し方・見つからないときの素のシェル、はそのまま。
   - **環境は新しいセッションにしか届かない**：既に動いている tmux のセッションの中は 256 色のまま。色を直したら 1 度セッションを作り直す（そのタブで `exit` してから開き直す、または `tmux kill-session -t main`。中のプロセスは終わる）。この手順は Get Started の「色を PC の Ghostty にそろえる」に書く。
   - **見つからないとき**：「tmux が見つかりません（Mac で brew install tmux を入れると、切れても作業が残ります）。素のシェルを開きます」と出して、素のシェル（`$SHELL -l`）を開く。
   - **タブごとに別のセッション**：1 つ目のタブは `main`、2 つ目からは `main-2`・`main-3`…（`tmux=` の名前に `-番号`。番号は、同じ接続先で開いているタブが使っていない最小のもの。`TabSlots`）。タブの題名も `mac`・`mac 2`…（接続先の題名が来たら `mac 2 · 題名`）。＋も ⌘T も同じ。タブを閉じても tmux のセッションは残し（kill しない）、次に開いたタブが同じ番号なら、そのセッションに戻る。止まるのは、シェルでプロセスを終わらせたときだけ。`tmux=none` のタブは、番号に関わらず素のシェル。
   - **裏に回っても約 30 秒は繋いだまま**：裏に回ったとき、繋がっているタブが 1 つでもあれば、iOS のバックグラウンドの猶予（`beginBackgroundTask`。約 30 秒、全タブで 1 つ）を取る。猶予が切れる前に、自分で全タブの接続を閉じ（状態は「裏に回ったので切りました」。再試行は予約しない）、猶予を返す。猶予の前に前面へ戻れば、接続はそのまま続く。`reconnect = false` のときは、自分で閉じたタブも前面に戻って勝手には繋がず、タブのタップで繋ぐ。
   - **繋ぎ直す場面**：次の場面で自動で繋ぎ直す。
     - 前面に戻った（切れていれば、待たずにすぐ。猶予が切れて自分で閉じたタブも、ここで繋ぎ直して同じ tmux のセッションに戻る）
     - 通信が切れた（0 秒、0.5 秒、1 秒、2 秒、4 秒、8 秒、以降 15 秒おき。裏にいる間は試さない）
     - 回線の種類が変わった（Wi-Fi ⇄ 5G。TCP は続かないので、切れたと分かるのを待たずに繋ぎ直す）
   - 接続先のシェルが終わった（exit や tmux の detach）ときと、ホスト鍵の拒否・認証の失敗では繋ぎ直さない（最初に起きた原因で見分ける）。タブをもう一度タップで繋ぎ直す。
   - 握手（TCP・鍵交換・認証・端末を開く）が 20 秒で終わらなければ止める。ホスト鍵の確認やパスワードを人に聞いている時間は数えない（聞き終わったら改めて 20 秒）。
   - つないでいる途中でタブを閉じたら、その接続は端末を開く前に止める（閉じたタブの tmux のクライアントを残さない）。
   - 切れた接続は TCP の keepalive（`keepalive = 15s`）で早めに見つける。スクロールバックは繋ぎ直しても残す。
2. **計測**：再接続にかかった時間（signpost `reconnect`）と、切断が起きた場面を端末内のログ（os_log）だけに記録する。
3. **判断**：移動中の利用で不満が残れば、Eternal Terminal を先に試す。予測表示まで必要になったら mosh を検討する。

## セキュリティ要件

鍵は端末の外へ出さず、ターミナルの内容はどこにも送らず、ディスクにも残さない。この 3 点を軸にする。

| 項目 | 要件 |
| --- | --- |
| 鍵の生成 | Secure Enclave で生成する ECDSA P-256 鍵（端末から取り出せない）。キーチェーンには Secure Enclave の外では使えない包みだけを「最初のロック解除の後・この端末だけ」で置く（画面を消している間の再接続でも使えるように） |
| 公開鍵の登録 | 公開鍵（秘密ではない）を書類フォルダの `splitterm.pub` に置く。Mac では `scripts/ios_pubkey.sh` が取ってきて `authorized_keys` に足す。このファイルは「ファイル」アプリから書き換えられるので、1 行だけのときに限り、その行の指紋をアプリの表示（＋を長押し →「公開鍵をコピー」）と見比べる（端末で y、または `--fingerprint` が一致したときだけ）。アプリが書く形（`ecdsa-sha2-nistp256 … splitterm`）以外の行は受け付けない。足す行には `restrict,pty` を付け、端末以外（ポート転送・エージェント転送など）を止める |
| ホスト鍵 | 初回接続時に SHA256 の指紋を見せて確認し、保存する。変わっていたら接続を止めて警告する（受け入れる道は作らない。消すのは＋を長押し →「このタブのホスト鍵を忘れる」） |
| 認証方式 | 公開鍵認証だけが既定。パスワード認証は config の `password-auth` か host の `auth=password` で許したときだけ、毎回聞いて保存しない |
| アプリロック | アプリを開いていない時間が `app-lock-after`（既定 15 分）を超えたら、次に開くときに Face ID（かパスコード）を求める（`app-lock`。0 なら裏に回るたび）。開いていない時間は裏に回った時刻から測り、端末を再起動した・時計が戻った・記録が無いときはロックする。Touch ID の位置のキーで今すぐロックできる。ロック中は、画面のキーボード・ハードウェアキーボード・タッチの入力をすべて捨てる。起動時の自動接続はロックを解いてから。覆いは最前面の別のウィンドウに出す（アラートや「調べる」の画面より上で、キー入力も覆いが受ける）。裏に回るときは Face ID の途中でも必ず覆う。Face ID をやめたら繰り返し求めず、覆いのタップでもう一度。端末にパスコードが無いときは、ロックを解く手段が無いのでロックせず、そのことを知らせる |
| 接続情報の保存 | 接続先は config（秘密を含まない）。鍵とホスト鍵はキーチェーンで、iCloud には同期しない |
| 画面の保護 | アプリスイッチャーではターミナルの内容をぼかす（`privacy-blur`） |
| 守りを弱める設定 | config は「ファイル」アプリや Mac のエージェント（`splitterm` の `config_push`）から書き換えられる。`app-lock`・`privacy-blur`・`media-strip-location` を false に、`app-lock-after` を長くする変更は、何を外すかを示した本人の確認（Face ID かパスコード）の後でだけ効かせる（ロック中に届いた変更も、ロックを解いた後に別に確かめる）。効いている値は端末の中に別に覚える（初めは守る側） |
| 鍵の読み出しの失敗 | キーチェーンが読めないとき（ロック中など）は、鍵を作り直さない（作り直すと登録した鍵が使えなくなる）。端末の鍵が読めなければ、原因を出して接続しない。ホスト鍵が読めなければ、初めての接続先とも鍵が変わったとも扱わず、接続を止める |
| クリップボード | 選んだ文字（ダブルタップ・長押しを離したとき・⌘C・「コピー」）は、他の端末へ渡さない形（`localOnly`）で、表示を出さずに自動でクリップボードへ載せる。前面にいる間は期限を付けない。アプリを離れたとき、中身がまだアプリの載せたもの（`changeCount` が覚えた値と同じ）で `clipboard-clear`（既定 60 秒）が 0 より大きければ、同じ文字を期限付きで載せ直す（期限は OS が管理するので、アプリが止められても効く）。前面に戻ったとき、まだアプリの載せたもので期限が来ていなければ期限を外して載せ直し、過ぎていれば何もせず覚えていた文字を捨てる。中身は読まず（「ペーストの許可」を出さない）、比べるのは `changeCount` だけ。載せ直し用の文字はメモリにだけ持つ。`clipboard-clear = 0` は消さない。公開鍵のコピーは対象外。**残るリスク**（OS の全体の置き場に出る、選ぶだけで載る、前面のまま終了すると期限が付かない、離れてからの期限までの間は他のアプリが読める）は、アプリだけでは守りきれない。issue #4 を参照 |
| 接続先に許すこと | 接続先は信頼しない（SwiftTerm の `isProcessTrusted` を false）。画面の中身のチェックサムの問い合わせ（DECRQCRA）と作業ディレクトリの通知（OSC 6・7）に答えない。クリップボードの読み書き（OSC 52）と、題名の送り返しなどの窓の操作には答えない。画像は描かない。kitty の画像は受け取らない。sixel は対応していると答えないが、SwiftTerm に解釈を止める公開の口が無いので、送られれば SwiftTerm の上限の中で解釈される。タブに出す題名は制御文字と双方向の書式文字を除き、40 文字に切る。題名・ベル・モードの知らせは、連打されてもメインスレッドへは 1 回にまとめる |
| 受信の量 | 解析待ちが 8MB を超えたら受信を止め（SSH の窓が広がらず、接続先が待つ）、1MB まで減ったら再開する |
| 貼り付け | 貼る文字からタブと改行以外の制御文字（ESC など）を除く。括弧付きペーストが無効な所へ複数行を貼るときは、行ごとに実行されることを見せて確かめる |
| かな漢字変換 | 学習しない（打った語をディスクに残さない） |
| 依存 | 公式か広く使われ保守の続く最新の版だけを使う。SwiftTerm と AzooKey は小さな版までに止め、新しい版が出たら上げる |
| 外部送信 | テレメトリ、クラウド同期、AI 機能を持たない |
| ログ | セッションの内容をディスクに保存しない。スクロールバックはメモリ上だけに置く |
| 拡張（ハーネス） | API キーは接続先の PC だけに置き、アプリには保存しない。アプリとハーネスの通信は SSH の中を通す |

## 配布

使うのは自分 1 人なので、lfm3-vl-server の iPhone アプリ（同リポジトリの `docs/native-app.md` §9）と同じく、無料の Apple ID（Xcode の Personal Team）で署名し、Mac から入れ直す。有料登録をしないので、App Store・TestFlight・Web から入れる OTA は使わない。

- 無料の署名の制約：アプリは 7 日で起動できなくなる（入れ直しが要る）、1 台に入れられるのは 3 本まで、App ID は 7 日に 10 個まで。Bundle ID（`io.github.dken-devcat.mobile-ssh-client-split-keyboard`）は変えない（キーチェーンの鍵もこれに付く）。
- Team は git に入れない（`ios/Config/Local.xcconfig`。スクリプトは Xcode の設定から無料の Team を読む）。

準備（1 回だけ。コマンドは README）：

1. Xcode に Apple ID でサインインする（Personal Team ができる）
2. iPhone・iPad を USB でつないで信頼し、デベロッパモードをオンにする
3. `scripts/ios_reinstall.sh` で入れる。初回は証明書・端末の登録・App ID・プロファイルが自動で作られる
4. 端末の「設定 > 一般 > VPN とデバイス管理」で開発元を信頼する
5. launchd に `launchd/com.dken.splitterm-ios.plist` を登録する
6. `scripts/ios_push_config.sh --init` で config を作って host を書き、`scripts/ios_push_config.sh` で送る。Mobile-SSH-Client---Split-Keyboard を一度開いてから `scripts/ios_pubkey.sh` で公開鍵を Mac に登録する

自動の入れ直し（launchd が `scripts/ios_reinstall.sh --if-needed` を 1 時間ごとに呼ぶ。スクリプトは lfm3-vl-server のものをそのまま移し、テストも移した）：

1. 入れたアプリの期限の残りが 48 時間を切ったら、入れ直しにかかる。記録が無ければ入れ直しは要るとみなすが、急ぎにはしない
2. メモリの圧迫が「通常」でなければ見送る。端末に届かなければ見送る
3. 端末がロックされているか、Mobile-SSH-Client---Split-Keyboard が動いていない時に入れる（使っている最中にアプリを閉じないため）。残りが 12 時間を切ったら待たない
4. このアプリの手元のプロファイルのうち残りが 48 時間を切ったものをどけてから、`xcodebuild -allowProvisioningUpdates` でビルドし、新しい 7 日のプロファイルを受け取る
5. 新しいプロファイルの残りを確かめてから `xcrun devicectl device install app` で入れ、Mac の通知で知らせる
6. 失敗は Mac の通知とログで知らせる。同じ失敗が続く間は最初の 1 回だけ

入れ直しても書類フォルダ（config・公開鍵）とキーチェーン（Secure Enclave の鍵・ホスト鍵）は残る（lfm3-vl-server の N0 で確かめた）。

## メディアを送る

📎 から写真・動画を選ぶ・撮る・録音する・ファイルを選ぶと、同じ SSH の接続で接続先の受け取り箱（`media-dir`）へ送り、届いたファイルのパスを入力行に入れる（Enter は押さない）。Claude Code などのエージェントは、そのパスで読む。

### iOS の制限で落とさない

| 入口 | 使うもの | 落とさないための設定 |
| --- | --- | --- |
| 写真・動画を選ぶ | PHPicker（写真へのアクセスの許可が要らない） | `preferredAssetRepresentationMode = .current`（HEIC・HEVC・ProRAW を変換しない）。複数選べる |
| 撮る | UIImagePickerController | 画質 `.typeHigh`、長さの上限 4 時間（既定は 10 分） |
| 録音 | AVAudioRecorder | AAC 48kHz、時間の上限なし |
| ファイル | UIDocumentPicker | どの形式でも |

### 何を送るか（`MediaPlan`）

| `agent` | 画像 | 動画 | 音声 |
| --- | --- | --- | --- |
| `claude-code`（既定）・`codex` | png・jpeg・gif・webp は原本。ほか（HEIC など）は JPEG（品質 0.92、大きさは変えない） | コンタクトシート＋添え書き（文字起こし） | 文字起こし |
| `generic` | png・jpeg は原本。ほかは JPEG | 同上 | 同上 |
| `agent-media` で `video`・`audio` を足したとき | 同上 | 原本 | 原本 |

`video-mode`・`audio-mode` で、いつも原本・いつもシート（文字起こし）・両方、も選べる。

位置情報は既定で外す（`media-strip-location = true`）。外せなければ送らない（原本をそのまま送ることはしない）:

- 写真: メタデータの GPS（EXIF と XMP）だけを外して写す（再圧縮しない）。書き戻せない形式（RAW・WebP など）は JPEG にして外す
- 動画・m4a: 映像と音声のトラックだけで組み直し、再エンコードせずに書き出す（メタデータと時系列のメタデータのトラックは持っていかない。iPhone の動画にふつう付く向き・明るさのトラックや、GoPro・ドローンの位置のトラックも）
- 外した後に読み直して、位置情報が残っていないことを確かめる。もともと位置情報が無ければ手を加えずに送る（GIF のアニメーションも残る）。PDF・テキスト・mp3・wav など、位置を持たない形式はそのまま。拡張子が無い・知らないものは中身を見て決める
- `media-strip-location` を false にする変更は、`app-lock` と同じく本人の確認（Face ID かパスコード）の後でだけ効く（config は Mac のエージェントからも書き換えられるので）

### 送り方

- 名前はアプリが付ける（`20261030-101010-ab12.heic`。日時と乱数だけ）。接続先で動かすコマンドは決まった文字列に、確かめた受け取り箱の場所（`~/` か `/` で始まる英数と `. _ - /`。ホームや / そのものは不可）と名前と SHA-256 だけを入れる（`RemoteCommands`）。
- コマンドはどれも `exec /bin/sh -c '…'` の 1 行（ログインシェルが fish・tcsh でも同じに動く）。
- 端末とは別のチャンネルで `exec` する（PTY は開かない）。`umask 077`、受け取り箱を作り、自分の持ち物か（`[ -O . ]`）を確かめ、古いもの（`media-retention`）を消し、途中まで届いている大きさを聞く → 続きを `cat >>` で送る（256KB ずつ、書き終わるのを待ってから次。SSH の窓が流れを決める）→ SHA-256 が合えば `.part` を外し、印（`splitterm-done`）を出す。合わなければ消して、もう 1 度だけ最初から。
- 古いものとして消すのは、アプリが付けた名前（`20261030-101010-ab12.*`）のファイルだけ。受け取り箱に人が置いたものは消さない（Mac の `splitterm inbox clean` も同じ）。
- 終わりは終了コードと印で判断する（ログインシェルの出す文字と取り違えない）。受け取り箱を作れない・自分の持ち物でない・SHA-256 を計る道具（shasum・sha256sum・sha256・openssl）が無いときは、決まった終了コードで止め、繰り返さずに理由を出す。
- 切れたら、繋ぎ直しを 30 秒まで待って、同じ名前で続きから（3 回まで）。SHA-256 は 1 度だけ計る。裏に回っても、iOS が許す間は送る。
- 何も進まない時間が 60 秒（終わりの確かめは 15 分）続いたら止める。送っている間は 📎 から「送るのをやめる」。
- パスは、送った元のタブの入力行に入れる（改行は入れない。ロック中に送り終わったら、ロックを解いてから入れる）。
- 送っている間は、同じ TCP の上で端末の打鍵とメディアが流れる。遅い回線で打鍵がどれだけ遅れるかは、実機で測る（遅れるなら、送る速さを絞るか、送る接続を分ける）。
- SFTP は使わない（swift-nio-ssh に SFTP のクライアントが無く、接続先で切られていることもある）。

## 動画を画像にして送る

画像は読めるが動画は読めないエージェントへ、動画を少ないトークンで渡す。処理はすべて端末の中で、軽くする。

1. **下見**: 64px の縮図を 0.5 秒ごと（最大 240 枚）に取り、8×8 の明るさの前との差を点数にする。全解像度は読まない。
2. **選ぶ**: 時間を枚数の区間に分け、各区間で最も変わった時刻を選ぶ（最初の 1 枚は先頭）。既定 12 枚、10 秒未満は半分（`ContactSheetPlanner.select`）。
3. **並べる**: 選んだ時刻だけを、タイルの大きさで取る。シートの長い辺は 1,568px（`video-sheet-size`）。並びは、シートが 16:9 に近くなるもの（16:9 の動画 12 枚は 4×3 で 1,568×660、縦長の動画は 6×2）。各タイルの左下に時刻。JPEG 品質 0.8。
4. **文字起こし**: `SFSpeechRecognizer`（日本語）を `requiresOnDeviceRecognition` で。端末にモデルが無ければ、外へ送らずに飛ばす（添え書きに理由を書く）。
5. **添え書き**: 長さ・解像度・各タイルの時刻・文字起こしを Markdown 1 枚（`*.video.md`）に。シートと添え書きのパスを入力行へ。

| 送り方（Claude、幅×高さ÷750） | 目安のトークン |
| --- | --- |
| 12 枚を 1,568×882 で別々に | 約 22,100 |
| **コンタクトシート 1 枚（4×3、1,568×660）** | **約 1,400** |
| ＋ 1 分の文字起こし | 約 300〜500 |

軽さの目標: iPad 第 6 世代（A10）で 1 分の 1080p の動画を 3 秒以内（文字起こしを除く）、メモリ 50MB 以内。

## Get Started と MCP

### Mac の `splitterm`（CLI と MCP）

`ios/TermCore` の依存の無いパッケージにある（数秒でビルドできる）。config の読み取りはアプリと同じ `TermCore` なので、検査の規則がずれない。`splitterm mcp` で MCP サーバー（stdio、1 行に 1 つの JSON-RPC）になる。ネットには出ない。外のプログラム（scripts/ と、`theme import` が呼ぶ `ghostty`）はシェルを通さずに起動する。

| 道具（MCP） | CLI | すること |
| --- | --- | --- |
| `doctor` | `doctor` | Xcode・無料の Team・jq・tmux・リモートログイン・端末・config・アプリ・公開鍵を調べ、直し方を返す。人の手が要るものに印（needs_human） |
| `config_show` / `config_check` | `config show` / `config check` | 今効いている値 / 読めない行 |
| `config_set` | `config set KEY VALUE` | 1 項目を書き換える（コメントと並びを残す。読めなくなる書き換えと改行の混入は断る） |
| `host_add` / `host_remove` | `host add` / `host remove` | 接続先を足す・消す |
| `config_push` | `push` | 端末へ送る（読めない行があれば送らない） |
| `pubkey_install` | `pubkey --fingerprint` | 公開鍵を authorized_keys へ（アプリに出た指紋が要る。`restrict,pty` 付き） |
| `app_install` / `app_status` | `install` / `status` | 入れ直す / 期限 |
| `inbox_list` / `inbox_clean` | `inbox list` / `inbox clean` | 端末から届いたメディアの一覧（新しい順）/ 古いもの（アプリが付けた名前のものだけ）を消す |
| `theme_import`（引数 `dry_run`） | `theme import [--dry-run]` | Mac の Ghostty が使っている配色を config に書く（`--dry-run` は書き換える内容と警告を出すだけ）。端末へは `push` で送る |

- 道具が触る config は決まった 1 つだけ（ファイルの場所は受け取らない。CLI の `--file` は人が使う）。`theme_import` が読む Ghostty の config とテーマも決まった場所だけで、場所は受け取らない。守りを弱める変更は、端末へ送っても、端末で本人が確かめるまで効かない（「セキュリティ要件」）。
- `pubkey_install` の指紋は、人がアプリの画面から読んだものを渡す約束（道具は形を確かめるだけで、エージェントが公開鍵のファイルから自分で計算した指紋を見分けられない）。手順書と道具の説明でエージェントにそう伝える。
- 外のプログラムが時間切れになったら止め、孫のプロセスが出力を持ったままでも 5 秒で見切る（MCP サーバーが止まらない）。1 行は 1MB まで。

#### Ghostty の配色の取り込み（`theme import`）

「色」②。Ghostty が実際に使っている値を読み、config に書く。

- **読み方**（上から順に試す）：
  1. `ghostty +show-config --changes-only=false`（テーマを当てた後の全部の値）を、シェルを通さずに起動して読む。場所は `/Applications/Ghostty.app/Contents/MacOS/ghostty`、無ければ PATH の `ghostty`。時間切れ（10 秒）と出力の上限（1MB）は外のプログラムの起動の仕組みに従う。`key = value` の行として読み、知らない行は飛ばす（出力の形は版で変わりうる）。
  2. 起動できない・読めないときは、Ghostty の config ファイル（`$XDG_CONFIG_HOME/ghostty/config`。`$XDG_CONFIG_HOME` が無ければ `~/.config/ghostty/config`。続けて `~/Library/Application Support/com.mitchellh.ghostty/config`。後に読んだ方が優先）とテーマのファイル（`theme = 名前` → `$XDG_CONFIG_HOME/ghostty/themes/名前`〔`$XDG_CONFIG_HOME` が無ければ `~/.config/ghostty/themes/名前`〕、無ければ `/Applications/Ghostty.app/Contents/Resources/ghostty/themes/名前`。名前に `/` を含む・`.` で始まるものは読まない）を直接読む。テーマの値の上に config の値を重ねる。この道では、明示されていない色は Ghostty の既定色が分からないので書かず、そのことを出力に書く（色以外の `minimum-contrast`・`bold-is-bright`・`font-thicken`・`window-colorspace` は、明示がなければ Ghostty の既定値の 1・false・false・`srgb` と見なす）。
  3. どちらでも見つからなければ、直し方（Ghostty を入れる・置き場所）を添えたエラーにする。
- **書く項目**（Ghostty → splitterm）：

| Ghostty | config |
| --- | --- |
| `background`・`foreground`・`cursor-color`・`selection-background` | 同じ名前（未設定のものは書かない） |
| `palette = N=#RRGGBB`（N が 0〜15） | `palette = N=#RRGGBB` |
| `minimum-contrast`・`bold-is-bright`・`font-thicken` | 同じ名前 |
| `window-colorspace`（`srgb` / `display-p3`） | `color-space` |

- **明暗 2 つのテーマ**（`theme = light:A,dark:B`）は暗い方（B）を使う（アプリは暗い画面だけ）。`+show-config` の出力に明暗 2 つの `theme` があるときは、どちらの値が出ているか分からないので、ファイルの道で暗い方を読み直す（読めなければ出力の値を使い、警告する）。
- **色の書き方**は `#RRGGBB`・`RRGGBB`。それ以外（X11 の色の名前など）は書かずに警告する。
- **palette の 16〜255** は取り込まない（xterm の標準と同じため）。標準と違う値があれば、警告だけ出す。
- **書き方**は `config set` と同じ（`ConfigEditor`。コメントと並びを残し、読めなくなる書き換えは断る）。`--dry-run` は書き換える内容と警告を出すだけで、何も書かない。出力の最後に、次は `splitterm push` で端末へ送る、と書く。

### サイトと AIO

`site/`（Markdown から標準ライブラリだけの `site/build.py` で作り、生成物も git に入れる。Cloudflare 側ではビルドしない）。すべてのページに Markdown の双子、`llms.txt`・`llms-full.txt`、JSON-LD、`robots.txt`（AI のクローラを許す）、`sitemap.xml`、安全なヘッダー（`_headers`）。費用は 0 円（Cloudflare Pages の無料枠、公開リポジトリの GitHub Actions）。ベンチマークは `bench/`（A: 静的な検査を CI で毎回、B: 手元の `claude -p` に課題を解かせる、C: AI 検索での見え方を手で記録）。詳細は `site/README.md` と `docs/proposal-2026-10-30.md`。

#### 見た目

- **元の絵**：`brand/app-icon.svg`（1024px。角丸は iOS が付ける。文字は JetBrains Mono Bold を輪郭にしてあり、フォントが無くても同じに描ける）と `brand/favicon.svg`。PNG・ICO は `node scripts/gen_brand.cjs` で作る（Chromium で描く）。PNG を直接いじらない
- **トップのメインビジュアル**：デザイン（1600×900）の寸法を `calc(N * var(--u))` でそのまま書き、画面の幅と高さに合わせて縮める（コンテナの単位 `cqw`。JavaScript は使わない）。デザインが変わったら数字を写すだけでよい。文字は画像にせず HTML のまま（検索と AI が読める）
- **フォント**：JetBrains Mono（OFL）をサイトから配る（ラテン文字だけ、可変の太さ、約 31KB）。日本語は OS のゴシック（ヒラギノ・游ゴシック など）。外のフォント配信（Google Fonts）は読まない（外へのリクエスト 0）

- **PC だけ**：モバイル向けの調整は後で（利用者の指示、2026-10-30）

## 拡張：エージェントハーネス

拡張として、軽量な Haiku を指揮役（オーケストレーター）にし、必要なときだけ上位モデルを呼ぶハーネスを作る。目的はエージェントの応答速度で、簡単な依頼は Haiku が即答し、難しい依頼だけを分解して並列に回す。

難しい依頼では、Haiku が作業手順を書き、手順ごとにモデル・指示・見せる文脈を決めて並列に実行する。結果を検証し、足りなければ手順を足す。

### 参考にする構成

Sakana AI の Conductor は、7B の小さなモデルが質問ごとに作業手順を書き、どのモデルに何を指示し、どの過去のやりとりを見せるかを決める。簡単な質問は 1 回の呼び出しで済ませ、難しいコーディング問題には計画・実行・検証の流れを組む。この研究は同社のマルチエージェント製品 Sakana Fugu の土台になっている（[Sakana AI](https://sakana.ai/learning-to-orchestrate/)、[Apidog](https://apidog.com/blog/what-is-sakana-fugu/)）。Conductor は強化学習で指揮役を育てているが、このハーネスはまず既製の Haiku に指示で指揮させる。

### 設計

- **動く場所**：接続先の PC。アプリはフロントエンドとして、依頼の入力と進行状況の表示だけを担う。処理と API キーは PC 側に置く。
- **指揮役（Haiku）の仕事**：①即答できるか判定する、②できなければ作業手順を書く、③各手順にモデル（Haiku / Sonnet / Opus）・指示・文脈を割り当てる、④独立した手順を並列に実行する、⑤結果を検証して統合する、⑥足りなければ修正の手順を足す。
- **速さの工夫**：最初の応答（受付と方針）は Haiku がすぐ返す。各ワーカーには必要な文脈だけを渡し、入力を短く保つ。
- **アプリ側の表示**：手順のツリーと各ワーカーの状態（待機・実行中・完了）をパネルで見せる。横持ちの中央（シェルの位置）に出し、シェルと切り替える。

### 段階

1. **固定パターン版**：Haiku が「即答」「1 モデルに委任」「計画・実行・検証」の 3 パターンから選ぶ。
2. **計測**：最初の応答までの時間、完了までの時間、結果の品質を記録する。
3. **自由な手順版**：手順を Haiku が自由に書く。指揮役の学習（Conductor のような強化学習）は将来の検討とする。
