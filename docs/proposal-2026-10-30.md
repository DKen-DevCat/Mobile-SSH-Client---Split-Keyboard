# 設計案: Get Started・AIO・メディア送信（2026-10-30）

状態: **レビュー待ち**（セルフレビュー済み）。承認後に `docs/design.md` へ取り込み、実装する。
依頼: ① Get Started を Cloudflare で静的配信し、エージェントが設定まで実行できる（MCP など）／② 運用・配信は 0 円、ドメインは取らない／③ 公開を見据えた AIO とベンチマーク／④ 写真・動画・音声（撮影も）を送る。エージェントが読める形式は iOS の制限で落とさない／⑤ 動画を読めないエージェントへ、トークンを食わない画像にして送る（処理はアプリで軽く）。

## 結論

- **Get Started は「人が読むページ」と「エージェントが実行する手順書」を同じ内容から出す**。`splitterm.pages.dev`（Cloudflare Pages の無料枠）に、HTML と同じ内容の Markdown・`llms.txt`・`llms-full.txt` を置く。人はエージェントに 1 行（「https://splitterm.pages.dev/get-started.md を読んで SplitTerm を入れて」）を渡すだけ。
- **アプリの設定と運用は、Mac で動く `splitterm` コマンドとその MCP サーバーで、エージェントが実行できる**。config の読み取りはアプリと同じ Swift のコード（TermCore）を使い、ずれない。端末に触る操作（config を送る・入れ直す・公開鍵の登録）は devicectl が要るので、MCP は Mac の中で動く（ネットには出ない）。
- **費用は 0 円**。Cloudflare Pages の無料枠（帯域無制限・ビルド月 500 回）、公開リポジトリの GitHub Actions、無料の Apple ID。ドメインは `*.pages.dev`。有料の API は使わない（ベンチマークは手元のエージェントのサブスクリプションで回す）。
- **AIO は「AI が正しく答え、正しく実行できるか」を測って直す**。静的な検査（CI、毎回）、エージェントに実際にやらせる課題（手元で、月 1 回と大きな変更のたび）、AI 検索での見え方（公開後、手で月 1 回）の 3 段で測る。
- **メディアは、同じ SSH の接続で Mac の受け取り箱（`~/.splitterm/inbox`）へ原本のまま送り、パスを入力行に入れる**（Enter は押さない）。iOS が勝手に縮めたり変換したりする道（写真の選び方・カメラの既定の画質と長さ）を避ける。エージェントが読めない形式のときだけ変換する。
- **動画は、場面の変わり目から選んだ 12 枚を時刻付きの 1 枚の画像（コンタクトシート）にし、音声は端末の中で文字にして添える**。1 分の動画が画像 1 枚（約 1,800 トークン）と短い文字になる。12 枚を別々に送るより 10 分の 1 以下。解析は 64px の小さな縮図で行い、全解像度で読むのは選んだ 12 枚だけ。

## 全体像

```
[iPhone・iPad: SplitTerm]
  写真・動画・音声・撮影 ─▶ 形式の判断（エージェントの読める形式）
     │                        ├ 読める: 原本のまま（位置情報だけ外す）
     │                        └ 読めない: 動画→コンタクトシート＋文字起こし / HEIC→JPEG など
     ▼
  SSH（同じ接続、検証済みのホスト鍵）── exec: 受け取り箱へ書く（続きから再開、SHA-256 で確認）
     ▼
[Mac]
  ~/.splitterm/inbox/  ◀── tmux の中のエージェント（Claude Code など）がパスで読む
  splitterm（CLI / MCP）── config の検査・変更・送信、公開鍵の登録、アプリの入れ直し、受け取り箱の一覧
     ▲                         │ devicectl
  手元のエージェント ◀─ 読む ── https://splitterm.pages.dev（get-started.md・llms.txt）
                                  ▲ Cloudflare Pages（無料）← GitHub の site/
```

## 1. Get Started とエージェントで実行できる設定

### サイト（`site/`、ビルドの手順なしの静的ファイル）

| パス | 中身 | 誰向け |
|---|---|---|
| `/` | 何か・誰向けか・必要なもの・3 分の流れ。エージェントに渡す 1 行をコピーできる | 人 |
| `/get-started` と `/get-started.md` | 準備の手順。各段に「実行するコマンド」「成功の確かめ方」「人の手が要る所（Apple ID・端末で信頼・Face ID）」を書く | 人とエージェント |
| `/config` と `/config.md` | config の全項目（`config.example` から作る。手で二重に書かない） | 人とエージェント |
| `/mcp` と `/mcp.md` | MCP の入れ方と道具の一覧 | エージェント |
| `/faq` と `/faq.md` | よくある質問（AIO の答えの元） | 人と AI 検索 |
| `/llms.txt` | 目次（llmstxt.org の形） | エージェント |
| `/llms-full.txt` | 全ページの Markdown をつないだもの（エージェントが 1 回で読む） | エージェント |
| `/robots.txt`・`/sitemap.xml`・`/_headers` | AI のクローラを許す、ページの一覧、安全なヘッダー（CSP など） | クローラ |

- HTML は Markdown から作る（`site/build.py`、Python の標準ライブラリだけ）。生成物も git に入れ、Cloudflare 側ではビルドしない（ビルドの回数を使わない、外の道具に頼らない）。
- config の項目の表は `config.example` から、最低 OS は `Base.xcconfig` から作る。ずれは CI で落とす。

### `splitterm` コマンドと MCP（Mac で動く）

`ios/TermKit` に実行ファイル `splitterm` を足す。TermCore の `ConfigParser` を使うので、アプリと同じ規則で検査する。`splitterm mcp` で MCP サーバー（stdio、依存なし）として動く。

| 道具 | すること | 人の手 |
|---|---|---|
| `doctor` | Xcode・無料の Team・jq・tmux・リモートログイン・端末の対・アプリの期限を調べ、足りないものと直し方を返す | – |
| `config_show` / `config_check` | config を見せる / 読めない行を行番号付きで返す | – |
| `config_set` | 1 項目を書き換える（コメントと並びを残す。書いた後に検査し、だめなら戻す） | – |
| `host_add` / `host_remove` | 接続先を足す・消す | – |
| `config_push` | 端末へ送る（`ios_push_config.sh`） | – |
| `pubkey_install` | 端末の公開鍵を authorized_keys に足す（`ios_pubkey.sh`） | – |
| `app_install` / `app_status` | 入れ直す / 期限・ビルドを見る | 初回だけ「信頼」 |
| `inbox_list` / `inbox_clean` | 端末から届いたメディアの一覧（新しい順、種類、元の動画との対応）/ 古いものを消す | – |

- 人の手が要る段（Apple ID のサインイン、端末で開発元を信頼、デベロッパモード）は、道具が `needs_human` と手順を返し、エージェントが人に頼む。
- 登録: `claude mcp add splitterm -- <repo>/ios/TermKit/.build/release/splitterm mcp`。Claude Code 以外の MCP クライアントも同じ stdio で使える。
- 安全: ネットに出ない（stdio だけ）。実行するのは決まったスクリプトだけで、引数は検査してから渡す（シェルを通さない）。秘密を返さない。

## 3. AIO とベンチマーク

### やること

- **答えの元を 1 か所に**: 何か・誰向け・必要なもの・最低 OS・料金（0 円）・できないこと を、トップと FAQ に同じ言葉で書く。名前は「SplitTerm」でそろえる。
- **機械が読める形**: すべてのページに Markdown の双子、`llms.txt`・`llms-full.txt`、JSON-LD（`SoftwareApplication`・`HowTo`・`FAQPage`）、`sitemap.xml`、正規 URL、`lastmod`。JavaScript なしで全文が読める。
- **クローラを拒まない**: `robots.txt` で GPTBot・OAI-SearchBot・ClaudeBot・Claude-SearchBot・PerplexityBot・Google-Extended・Applebot-Extended を許す。
- **言語**: 日本語を正本に、英語のトップ・Get Started・`llms.txt` を足す（質問は英語で来ることが多い）。→ 確認したいこと Q1

### ベンチマーク（`bench/`）

| 段 | 何を測る | いつ | 合格の線 |
|---|---|---|---|
| A. 静的な検査（`bench/aio_check.py`） | `llms.txt` の形、全リンク、HTML と Markdown の中身の一致、JSON-LD の型、robots の許可、sitemap の網羅、`llms-full.txt` の大きさ（4 万トークン以下）、config の項目と最低 OS が実装と同じか | CI で毎回 | すべて合格 |
| B. エージェントの課題（`bench/agent_bench.py`） | 手元の `claude -p` にサイトの URL だけを渡し、答えさせる・config を書かせる・手順を言わせる。採点は自動（キーワード、`splitterm config check`、手順の順序） | 月 1 回と、サイトを大きく変えたとき | 正答率 90% 以上、config の課題は全問 |
| C. AI 検索での見え方（`bench/visibility.md`） | Perplexity・ChatGPT 検索・Gemini で決まった質問をし、引用されるか・内容が正しいかを記録 | 公開後、手で月 1 回 | 記録して推移を見る（自動化しない。費用と利用規約のため） |

- B の課題の例: 「最低 iOS は？」（17）、「font-size を 12 にして mac に繋ぐ config を書いて」（検査に通る）、「Claude Code に動画を見せるには？」（コンタクトシートの説明）、「月いくらかかる？」（0 円）。
- B は「サイトを読ませない」場合と比べて伸びを見る（基準線）。結果は `bench/results/日付.json` に残し、前回と比べる。

## 4. メディアを送る

### 選び方と撮り方（iOS の制限で落とさない）

| 入口 | 使うもの | 落とさないための設定 |
|---|---|---|
| 写真・動画を選ぶ | `PHPickerViewController`（許可が要らない） | `preferredAssetRepresentationMode = .current`（HEIC・HEVC・ProRAW を変換しない）。複数選べる |
| 撮る | `UIImagePickerController`（カメラ） | 画質 `.typeHigh`、長さの上限を外す（既定は 10 分） |
| 録音 | `AVAudioRecorder` | AAC 48kHz、時間の上限なし |
| ファイル | `UIDocumentPickerViewController` | どの形式でも |

### 送り方

- 環境バーに 📎。選ぶと、エージェントの読める形式（下）を見て、そのままか変換かを決める。
- **同じ SSH の接続**に新しい exec のチャンネルを開き、決まったコマンド（`umask 077; mkdir -p ~/.splitterm/inbox; cat >> 名前.part`）に原本を流す。名前はアプリが作る（日時と乱数。接続先のシェルに渡す文字に、人が入れた文字は入らない）。
- 切れたら、繋ぎ直した後に受け取った大きさを聞いて続きから送る。最後に SHA-256 を比べてから `.part` を外す。裏に回ったら `beginBackgroundTask` で区切りまで送る。
- 届いたら、絶対パスを入力行に打つ（Enter は押さない）。形は `media-insert`（既定 `{paths} `）。
- 受け取り箱は送るたびに古いもの（既定 7 日）を消す。
- **位置情報を外す**（既定）。写真はメタデータだけ書き換え（再圧縮しない）、動画は再エンコードなしで書き出し直す。

### エージェントの読める形式（`agent` の既定。config で上書きできる）

| `agent` | 画像 | 動画 | 音声 | 根拠 |
|---|---|---|---|---|
| `claude-code`（既定） | png・jpeg・gif・webp | ✕ → コンタクトシート | ✕ → 文字起こし | Claude の画像入力 |
| `codex` | png・jpeg・gif・webp | ✕ → コンタクトシート | ✕ → 文字起こし | API のエラーが示す形式 |
| `generic` | png・jpeg | ✕ → コンタクトシート | ✕ → 文字起こし | 安全側 |
| （上書き）`agent-media = image,video,audio` | 原本 | 原本 | 原本 | 動画・音声を読めるエージェント用。Gemini CLI は要確認 |

- 読めない画像（HEIC など）は JPEG（品質 0.92）に。大きさは変えない（縮めるのはエージェントに任せる）。

## 5. 動画を画像にして送る（軽く、トークンを食わない）

### 流れ（すべて端末の中、裏のキュー、取り消せる）

1. **下見**: `AVAssetImageGenerator` で 64px の縮図を 0.5 秒ごと（最大 240 枚）に取り、8×8 の明るさの差で場面の変わり目を点数にする。全解像度は読まない。
2. **選ぶ**: 変わり目の大きい所を優先し、時間の偏りを避けて 12 枚（`video-frames`）。10 秒未満なら 6 枚。
3. **並べる**: 選んだ時刻だけをタイルの大きさで取り、4×3 の 1 枚（長い辺 1,568px、`video-sheet-size`）に並べ、各タイルの角に「mm:ss」。JPEG 品質 0.8。
4. **文字起こし**（`video-transcribe`）: 音声を `SFSpeechRecognizer` のオンデバイス（`requiresOnDeviceRecognition`）で日本語に。端末にモデルが無ければ、外に送らずに飛ばす。
5. **添え書き**: 長さ・解像度・各タイルの時刻・文字起こしを Markdown 1 枚に。シートと添え書きのパスを入力行へ。

### トークンの目安（Claude の画像は 幅×高さ÷750）

| 送り方 | 画像 | 目安のトークン |
|---|---|---|
| 12 枚を 1,568×882 で別々に | 12 | 約 22,100 |
| 12 枚を 1,092×614 で別々に | 12 | 約 10,700 |
| **コンタクトシート 1 枚（4×3、1,568×882）** | 1 | **約 1,800** |
| ＋ 1 分の文字起こし | – | 約 300〜500 |

- 1 タイルは 392×220px。細かい文字は読めないので、選んだ 1 枚を大きく送り直す操作（シートの時刻を指定）を足す。
- 軽さの目標: iPad 第 6 世代（A10）で、1 分の 1080p の動画を 3 秒以内（文字起こしを除く）。メモリは 50MB 以内。

## セルフレビューで直したこと

1. **MCP をクラウド（Cloudflare Workers）に置く案をやめた**。config を端末へ送る・入れ直すには Mac の devicectl が要り、リモートでは届かない。認証の口も増える。→ Mac の中の stdio にした。
2. **MCP を Node で書く案をやめた**。config の読み取りを JavaScript でもう 1 つ書くと、アプリとずれる。→ TermCore を使う Swift の実行ファイルにした（Xcode は配布で必須なので、増える前提はない）。
3. **SFTP をやめ、exec＋cat にした**。swift-nio-ssh に SFTP のクライアントが無く、接続先で SFTP が切られている環境もある。続きからの再開と SHA-256 の確認を足して、信頼性を補った。
4. **原本をそのまま送ると、写真の位置情報がエージェントの API まで流れる**。→ 位置情報を外すのを既定にし、再圧縮はしない。
5. **コンタクトシートの小さいタイルで細かい文字が読めない**。→ 1 枚を大きく送り直す操作と、枚数・大きさを config で変えられるようにした。
6. **文字起こしで音声が Apple のサーバーへ送られうる**。→ オンデバイスに限り、無ければ飛ばす。
7. **Cloudflare の Git 連携は、どのブランチの push でもビルドする**。→ ビルドしない静的ファイルにし、監視するパスを `site/**` に限る（月 500 回の枠を使わない）。
8. **AI のクローラが Cloudflare 側で止められているかは、こちらから設定できない**（`pages.dev` は自分のゾーンではない）。→ ベンチマーク A で、各クローラの名乗りで取得できるかを確かめ、だめなら GitHub（公開）を代わりの入口にする。
9. **ベンチマークを CI で回すと API の費用がかかる**。→ CI は静的な検査だけ。エージェントの課題は手元のサブスクリプションで回す。
